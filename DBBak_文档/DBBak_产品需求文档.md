# DBBak 数据库备份管理产品需求文档

面向 Windows Linux 与 Docker 的统一备份管理

配套文件：[开发文档](DBBak_开发文档.md) · [原型设计说明](DBBak_原型设计说明.md) · [HTML 交互原型](../web/index.html)

## 1 产品定位与交付范围

DBBak 面向运维人员与数据库管理员，通过 Web 控制台管理 SQL Server、MySQL 和 PostgreSQL 的备份任务，由后台执行周期备份、日志归档与旧文件清理。本文将用户所述 SQL 按 Microsoft SQL Server 处理。

正式版采用同一管理核心，提供 Windows 原生服务、Linux systemd 服务及 Docker Linux 容器镜像。关闭浏览器后继续调度。数据库可位于其他服务器；实际能力由数据库版本、所在系统、适配器和执行器共同决定。

| 角色 | 主要任务 | 成功标准 |
| --- | --- | --- |
| 系统管理员 | 部署服务 管理执行器与凭据 | 服务重启后配置与计划保持完整 |
| 运维操作员 | 配置任务 处理异常 预览清理 | 能确认最近可用备份与失败原因 |
| 数据库管理员 | 验证工具与恢复链 进行恢复演练 | 备份能够恢复到明确的目标时间 |
| 只读审计员 | 查看任务 日志与清理记录 | 操作与文件生命周期可追溯 |

### 交付边界

当前交付为浏览器交互原型，配置仅保存在本浏览器，执行和清理均操作样例数据。真实连接、服务端调度、访问控制、部署包和执行器尚未实现。本文规定正式版要求，不代表已有生产验收结果。

首版覆盖任务、周期、位置、全量及适配器支持的差异和日志备份，并按恢复依赖清理。跨区域高可用控制面、计费、数据库迁移及生产库一键覆盖恢复不在首版范围。恢复演练使用隔离目标。

## 2 部署方式与数据库能力

FR-01 跨平台部署。Windows 提供安装包与后台服务；Linux 提供可执行程序及 systemd 配置；Docker 提供镜像和 Compose 示例。发布包应声明操作系统、CPU 架构、依赖版本、升级方式与数据目录。Windows 原生部署不要求用户安装 Docker；Docker 首版交付 Linux 镜像。

| 数据库与路线 | 全量 | 差异 | 日志与前提 |
| --- | --- | --- | --- |
| SQL Server 原生备份 | 支持 | 支持 | 事务日志需有效基线与适当恢复模式 |
| MySQL mysqldump | 逻辑全量 | 不支持 | binlog 连续归档并记录位置或 GTID |
| MySQL 物理适配器 | 条件支持 | 条件支持 | 按工具版本 主机系统与许可验证 |
| PostgreSQL Linux pgBackRest | 实例全量 | 支持 | 配置数据库侧工具与 WAL 归档 |
| PostgreSQL Windows pg_basebackup | 实例全量 | 默认禁用 | 全量与连续 WAL 路线需兼容验证 |

上表为设计路线，不是已验证支持清单。SQL Server 差异依赖对应全量基线；MySQL 逻辑导出不能标记为物理差异；PostgreSQL 的 pg_dump 不能用作物理 WAL 恢复基线。pgBackRest 没有原生 Windows 端口，将仓库放入 Linux 容器不能自动支持 Windows 数据库主机。[S1][S2][S3][S4]

正式发布前须锁定已验证的数据库版本、主机系统、工具版本和执行方式组合。连接检测返回能力清单、前提条件与阻塞原因；不支持的模式不可选择或保存。用户切换适配器后，应重新检测能力，并提示检查受影响的任务。

管理端与执行端允许不同系统组合。执行器必须能到达数据库及备份仓库，且具备相应权限。SQL Server 文件路径由数据库服务访问；客户端导出的路径由执行器访问，界面必须明确显示路径归属。

## 3 数据源执行器与存储要求

FR-02 数据源与能力。用户创建数据源时填写引擎、实例地址、端口、版本、主机系统、备份范围与凭据引用。连接检测必须分别反馈网络、认证、备份权限、工具和日志归档条件，不能仅以端口连通认定备份可用。PostgreSQL 物理路线明确显示实例或集群范围。

FR-03 执行器。管理员可登记本地或远程执行器，查看所属系统、工具版本、心跳与并发上限，并为任务指定执行器。执行器离线时任务保持等待或失败状态，不产生成功记录。数据库侧工具、远程通信与工作目录访问方式必须可审计。

| 对象 | 核心配置 | 保存前检查 |
| --- | --- | --- |
| 数据源 | 引擎 地址 端口 范围 凭据引用 | 能力与恢复前提是否满足 |
| 执行器 | 系统 版本 标签 工作目录 | 身份 心跳 工具和目录权限 |
| 本地目录 | 执行器及绝对路径 | 目录归属 可写空间与权限 |
| 网络共享 | 共享地址 挂载点 凭据引用 | 执行端实际读写权限 |
| 对象存储 | 端点 Bucket 前缀 凭据引用 | 上传读取删除权限与连接配置 |

FR-04 存储位置。支持执行器本地目录、NAS 或网络共享，以及 S3 兼容对象存储。界面区分连接检查、格式检查和实际读写测试，展示路径所在主机。Docker 输出目录需映射到持久化目录或卷；管理服务的配置和元数据也须持久化。[S5]

关联中的数据源、执行器与仓库不得直接删除；先停用新任务、迁移引用并确认保留文件。修改仓库地址不能使旧备份失去定位，历史文件继续记录原仓库及对象标识。凭据不写入普通日志，也不随配置方案导出。

## 4 备份计划与执行控制

FR-05 备份计划。每个任务关联一个数据源、适配器、执行器和目标位置，分别设置全量、差异及日志计划。默认时区为 Asia/Shanghai，保存时保留时区信息。首次运行建立可用全量基线；缺少基线或日志链断裂时，应阻止依赖任务并提示补建全量。

| 项目 | 首版配置 | 规则 |
| --- | --- | --- |
| 全量 | 每日或每周 时间 星期 | 计划冲突时遵守实例互斥规则 |
| 差异 | 每日时间 | 仅能力检测通过后启用 |
| 日志 | 5 15 30 60 分钟间隔 | 按实际归档机制处理连续性 |
| 任务控制 | 立即执行 暂停 启用 | 暂停影响新调度 不默认中止正在运行 |
| 错过计划 | 记录未执行事件 | 默认不集中补跑 可手动补执行 |
| 高级计划 | 自定义 Cron 后续版本 | 需显示未来执行时间与时区 |

FR-06 执行控制。任务状态至少覆盖等待、运行、校验、成功、失败、取消和中断。运行记录包含唯一编号、触发方式、计划时间、实际时间、阶段、耗时与失败原因。只有工具完成、上传成功且必要检查通过后，备份才可标为可用。

同一实例或同一恢复链上的冲突任务不能并发执行。重复触发应复用或拒绝已有运行编号。重试必须有次数上限，并区分可重试网络异常、权限错误和基线缺失。服务或执行器重启后先核对原运行状态，不得直接将中断任务改为成功。

日志归档间隔用于设定恢复点目标，不能单独保证数据丢失上限。实际可恢复时间取决于最近成功归档、日志连续性和延迟。界面分别显示最近成功备份时间与最近可恢复时间，无法计算时显示原因。

## 5 备份目录与安全清理

FR-07 备份目录与恢复链。每份备份记录类型、引擎、工具版本、实例、仓库、文件标识、时间、大小、校验状态、基线或父备份引用及日志区间。逻辑上以实例、仓库和适配器组成保护组；保护组内计算保留规则，但仍须追踪跨组或历史迁移形成的实际依赖。

FR-08 保留与清理。同一保护组采用全局与关联任务中最长保留天数、最多全量份数。任一关联任务关闭自动清理时，该组不进行自动清理；手动清理仍允许预览，但必须通过同样的依赖保护和权限检查，并明确确认。

| 规则 | 必须保留的对象 |
| --- | --- |
| 恢复窗口 | 窗口起点所需基线及窗口内恢复点所需连续日志 |
| 最低份数 | 最近 N 份可用全量及所需依赖 |
| 运行与校验 | 正在写入 尚未确认或未验证的文件 |
| 锁定与保留 | 手工锁定 法务保留及其恢复依赖 |
| 最低安全线 | 最近一条有效恢复链及仍被引用的祖先 |
| 删除前复查 | 任务状态 保护标记 对象标识和依赖版本 |

不能仅按文件创建时间清理。系统先确定必须保留的恢复点和时间段，再计算依赖闭包；未知基线、缺失元数据或不连续日志应进入人工核查，不自动删除。新的全量完成并通过检查后，才能释放已无依赖的旧链。

清理预览列出可删文件、受保护文件、原因与预计释放空间。执行前重新计算；条件变化时要求刷新预览。删除按对象记录结果，部分失败可重试，审计记录独立保留。仓库文件清理不等于数据库原始日志截断。当前原型按整组采取更保守保护，正式版须按本文细化。

## 6 日志恢复验证与安全管理

FR-09 日志与告警。执行日志支持按任务、时间、引擎和结果检索，并可导出脱敏记录。失败、长期未成功、日志链断裂、仓库空间不足和执行器离线形成告警。重复告警合并，恢复后记录解除事件；通知发送失败应可见，不影响备份结果本身。

FR-10 恢复验证。文件校验与恢复演练分开展示。文件存在或校验和一致不等于数据库可恢复。产品应支持登记隔离恢复目标、发起或记录演练、展示所用链与恢复结果。首版不得默认覆盖生产实例，任何破坏性恢复须单独授权。

| 操作 | 管理员 | 操作员 | 只读用户 |
| --- | --- | --- | --- |
| 查看任务 日志与备份目录 | 允许 | 允许 | 允许 |
| 编辑任务 手动执行 | 允许 | 按授权 | 不允许 |
| 预览和执行清理 | 允许 | 单独授权 | 不允许 |
| 管理凭据 执行器与账号 | 允许 | 不允许 | 不允许 |
| 恢复演练及目标配置 | 允许 | 单独授权 | 仅查看结果 |

FR-11 权限与审计。凭据在服务端加密保存，任务只引用凭据标识；执行器通过认证通道领取必要权限，前端不接收可回显的明文。审计覆盖登录、配置变更、执行、取消、删除和权限调整，记录操作者、时间、对象及结果。数据库账号采用最小备份权限。

FR-12 配置与升级。支持导出不含凭据的配置方案，以及包含必要元数据的受控配置备份。升级前检查版本并备份配置，迁移失败可回退。更换部署方式时保留稳定任务标识、仓库定位和恢复链关系；删除程序不默认删除备份文件。

## 7 验收标准与质量要求

正式版按真实数据库和真实仓库验收，浏览器演示不能替代执行测试。测试记录须注明数据库版本、主机系统、工具版本、部署方式及恢复目标。性能指标在基准环境确定后填写；备份耗时与吞吐量不得脱离数据量、磁盘和网络条件承诺。

| 验收编号 | 对应需求 | 通过条件 |
| --- | --- | --- |
| AC-01 | FR-01 | 三类部署均能安装 启停 升级并保持配置 |
| AC-02 | FR-02 | 不支持模式不可保存 错误前提给出具体原因 |
| AC-03 | FR-03 | 离线执行器不误报成功 重连可核对任务 |
| AC-04 | FR-04 | 备份落入指定仓库 重建容器后仍可定位 |
| AC-05 | FR-05 | 按时区触发 暂停生效 错过计划可追踪 |
| AC-06 | FR-06 | 重复触发不重复写入 中断不伪造成功 |
| AC-07 | FR-07 | 全量 差异 日志的恢复依赖可准确追溯 |
| AC-08 | FR-08 | 较长策略生效 锁定链保护 过期无依赖可删 |
| AC-09 | FR-09 | 失败可检索 告警发送与解除有记录 |
| AC-10 | FR-10 | 在隔离目标完成恢复并记录目标时间 |
| AC-11 | FR-11 | 越权请求被拒绝 日志与导出不含凭据 |
| AC-12 | FR-12 | 升级迁移可回退 配置恢复后链关系完整 |

故障测试至少覆盖进程退出、主机重启、网络中断、磁盘满、对象上传失败及清理部分失败。对每类数据库至少验证一条全量恢复链；宣称支持差异或时间点恢复的组合，须另外完成相应恢复测试。清理测试必须覆盖保留窗口起点早于最近全量、混合策略和连续日志依赖。

控制台在桌面浏览器和窄屏下应可完成关键操作；状态不能只用颜色区分。所有破坏性操作需展示作用范围，后台再次校验权限与依赖。首次部署、任务配置和异常处理须有可执行说明。

## 8 迭代计划与决策事项

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 设计评审 | 需求 开发方案 原型与兼容计划 | 关键语义及候选环境确认 |
| 基础实现 | 三种部署 连接 工具适配 全量与日志 | 真实备份与恢复链验证通过 |
| 完整策略 | 差异适配 清理 告警 权限与审计 | 验收用例和故障测试通过 |
| 发布准备 | 安装升级 文档 兼容清单与恢复演练 | 全部声明能力具备验证记录 |

待项目启动确认的事项包括实际数据库与操作系统版本、规模及日变更量、允许的恢复点和恢复时长、仓库类型、异地副本要求、工具许可，以及告警渠道。开发排期需依据候选环境和验证结果制定，不以界面完成度推定后台已经可用。

主要风险是工具兼容性、数据库侧权限、日志链不连续及错误清理。产品通过能力检测、隔离恢复演练、保留依赖分析和删除前复查控制风险。兼容清单只列已通过验证的组合；新版本或新的工具路线按同一验收流程扩展。
